# v0.2.0 — the look, and the memory of a run

**Status:** planned, not started · **Written:** 2026-09-06 · **Follows:** v0.1.0

v0.1.0 is *a coding agent that works*. This is the version where it stops looking provisional and
stops starting from nothing every time.

Two different jobs in one version, and they are here together for a reason: both are things you can
only get right **after** using the thing daily. The visual pass needs a week of looking at it; the
shadow tree needs a week of noticing what you keep re-explaining.

## M1 — the terminal, properly

Everything [`docs/tui.md`](../tui.md) describes that v0.1.0 M3 scoped out, named there so the
deferral stayed visible:

- The ocellus beat — four frames on a 2.4-second cycle, and the rule that nothing else draws a
  ringed glyph.
- Collapsed blocks keeping their last two lines, anchored to the bottom with the cut faded rather
  than chopped. A row saying *thought · 213 words · Show* is a receipt.
- The diff renderer, in the permission card before a write and in the gutter row after it —
  including the one place this design uses colours that are not from the palette, because every
  diff a person has ever read is green and red.
- The syntax highlighting palette, which is a decision of its own: `rich` ships themes and none of
  them is brass and laurel.
- The `^K` overlays — the command palette, the todo board, the session picker — as floats in the
  same layout, never a second full-screen mode.
- The sub-80-column dock, where nothing is removed and only the resting state is quieter.

**First, because it is the thing being looked at.** It is also the milestone most likely to rewrite
`docs/tui.md` rather than implement it, and that is the intended outcome: everything in that
document was provisional until there was a build to argue with, and after v0.1.0 there is one.

## M2 — the shadow tree

`hera_code_shadow`: `shadow/`, `sketches/`, `thoughts/`, the note tools, and the index in the
project slot.

The load-bearing part is that **a shadow note is delivered with its file, never fetched**
([ADR 9](../adr/0009-a-shadow-note-is-delivered-with-its-file.md)). `code__read` returns the
contents and the note together. A note the model has to remember to ask for is a note that does not
get read — and delivery is also what makes a stale note survivable, because the note and the current
contents arrive in the same result and can be seen to disagree.

Sketches and thoughts work the other way and the asymmetry is the design: they are not about any one
path, so they arrive as an **index** — title and one line each — and the model reaches for the one
it wants. Exactly the shape of the skills catalogue.

**Cheap, and the payoff compounds.** It is a directory of Markdown files and one change to the read
tool.

## M3 — the graph

`hera_code_graph`: tree-sitter, the schema, incremental rebuild on a content hash, and the four
navigation tools — `graph_outline`, `graph_find`, `graph_neighbours`, `graph_path`.

The tools are shaped so that reading a whole file is the last resort, and **freshness is stated in
the prompt rather than implied**: an index a model cannot date is one it re-derives with `grep`
anyway, at which point the package has cost tokens and saved none.
[ADR 10](../adr/0010-navigation-before-reading.md).

**The write path is the part to get right first.** After `code__write` or `code__edit`, that file's
entry is stale in the same call. Being shown its own edit as though it had not happened is the one
staleness a person would never forgive, and it is trivial to prevent — so it is a test written
before the parser is.

**The cost worth naming up front:** grammar packs are the largest single contributor to binary size,
across five platforms. If that turns out worse than expected, the fallback is shipping the graph as
an optional download rather than dropping it — and that decision belongs in this milestone, not in
v0.1.0 M6 where it would be discovered.

## M4 — memory across repositories

`hera_memories` vendored, and the question it forces: hera-code would then have two memories. The
shadow tree knows about *this code*; `hera_memories` would know about *you*, everywhere.

That is a real distinction and probably a good one — *prefers explicit over clever*, *runs the tests
before saying it works* — but it is stated as a question rather than a plan because the two want
designing together. A memory that duplicates a thought is worse than either alone.

**This milestone may turn out to be an ADR and no code.** That is an acceptable outcome and it is
why it is last.

## M5 — instructions that follow the tree

Nested `AGENT.md` discovery: a file in a directory applies to work in that directory, resolved
lazily as files are touched rather than walked up front. And skills synced from a git repository, so
`~/.hera/skills` can track something shared.

Small, and here rather than in v0.1.0 because root-level instructions are enough to be useful and
nested ones are only worth it once there is enough context pressure to care.

## Not in v0.2.0

- **hera reaching hera-code** — v0.3.0, unchanged.
- **A sandbox** — v0.3.0.
- **Ranking or embedding in the graph.** It answers, it does not decide. A graph that guessed would
  be a retrieval system, and retrieval picking the wrong thing is the failure hera's ADR 5 spent a
  whole record on.
- **Pruning the shadow tree.** Nothing is deleted for you. A note for a deleted file stays orphaned
  until a person removes it, and the tree mirrors the source tree so that finding the orphan is the
  same act as noticing the file is gone.

## Not decided

Whether the graph should index test files the same way as source. Tests are the best available
answer to *what does this actually do*, and they are also most of the symbols in a healthy
repository — so indexing them fully may be the single most useful thing here, or the thing that
drowns every `graph_find` in fixtures. Worth measuring on this repository before choosing.
